## 2. Findings (detail)

### B1 — Next.js 16.2.4: critical RCE advisories (Blocker)

- **Evidence:** `app/package.json` → `"next": "16.2.4"`. `pnpm audit` lists 25 advisories against `next`. The critical ones:
  - *Unauthenticated RCE in Image Optimization API when AVIF files are used* (`<16.3.3`)
  - *Unauthenticated RCE on Windows-hosted servers* (`<16.3.3`)
  - *RCE in next/og ImageResponse* (`>=16.2.0 <16.3.6`). `next/og` is not used, but the fix ships in the same version.
  - Highs include several *Middleware/Proxy bypass* advisories. These matter once we add `proxy.ts` for CSP/auth (sections 3.1 and 3.2).
- **Reachability:** `app/next.config.ts:14-15` allows `{ hostname: "**.r2.dev" }` / `**.r2.cloudflarestorage.com`, and `app/next.config.ts:30` enables `formats: ["image/avif", ...]`. Anyone can create their own `*.r2.dev` bucket, so the vulnerable `/_next/image?url=https://<attacker>.r2.dev/...` path takes attacker-controlled input with no auth.
- **Fix:**
  1. Upgrade `next` and `eslint-config-next` to **≥ 16.3.6** (latest at audit time is 16.3.8). Re-run `pnpm audit` and `next build`.
  2. Pin `remotePatterns` to the **exact** bucket host (e.g. `pub-<id>.r2.dev` or the `R2_PUBLIC_URL` custom domain). Drop the `**` wildcards.
  3. Keep AVIF only after the upgrade. Pinning the host alone is not enough.

### B2 — Unauthenticated, unused print API routes (Blocker)

- **Evidence:**
  - `app/src/app/api/print/route.ts:45` `GET` → TCP connect to `ip:port` from config/env. It returns `printer:true/false`, which works as a port-probe oracle.
  - `app/src/app/api/print/route.ts:189-226` `POST` → `...body` is spread over the store fields (`:212`), then raw bytes go to `ip:port`. `toTIS620` passes all ASCII below 0x80 (`:68`), **including ESC/GS control bytes**. If `PRINT_BRIDGE_URL` is set (`:192-201`), the unauthenticated body is relayed to the bridge **with the server-held `PRINT_BRIDGE_TOKEN`** (confused deputy).
  - `app/src/app/api/print/config/route.ts:15-17` `GET` returns the whole config. `:19-35` `PUT` accepts any `ip` (no private-range check) and any `port` (`Number()` only), then calls `fs.writeFileSync`. `body.ip.trim()` throws on non-strings, and `err.message` is echoed back (`:38`).
  - `app/src/app/api/print/scan/route.ts:29-41` sweeps 254 hosts per unauthenticated request (DoS amplification and LAN reconnaissance when self-hosted).
  - **No client uses them.** A grep for `/api/print` in `src` (outside `app/api`) returns 0 hits. Printing goes through `src/lib/printer-bridge.ts` → `http://127.0.0.1:8080`.
  - **Prod confirmation (passive GET):** `https://cafe-pos-sable.vercel.app/api/print/config` → **200**, keys `storeName, storeAddress, storeTaxId, storeBranch, ip, port, mode, printerName`. `app/printer-config.json` is also committed to git.
- **Impact:** On Vercel, the FS is read-only and LAN IPs are unreachable, so this is limited to info disclosure, an outbound-probe oracle, and a bridge relay if `PRINT_BRIDGE_URL`/`PRINTER_IP` are set. Self-hosted (`next start -H 0.0.0.0` on the shop PC) it becomes an internet/LAN-reachable SSRF: rewrite the printer IP to any host:port, then write attacker bytes to it, plus fake receipts.
- **Fix (recommended):** **Delete** `src/app/api/print/**` and `app/printer-config.json` (the bridge owns printer config). If the routes are ever needed again, see section 3.4 for the auth and IP-allowlist design.

### M1 — Tokens in localStorage (Major)

- **Evidence:** `app/src/lib/token-store.ts:1-2,33-41` stores `cafe_pos_token` / `cafe_pos_refresh_token` in `localStorage`. `app/src/lib/auth.ts:15-27` sends the refresh token from JS. `app/src/lib/api-client.ts:51-60` attaches `Authorization: Bearer` from JS. `app/src/components/screens/login.tsx:67-88` stores the login response.
- **Backend facts** (`caf-pos-repo-main/api/app`):
  - `core/security.py`: HS256, `JWT_SECRET` (≥16 chars, `config.py:14-15`).
  - Access token 480 min, refresh token 30 days (`config.py:16-17`).
  - Login returns JSON `{access_token, refresh_token, token_type}` (`schemas/auth.py:11-14`).
  - Refresh takes JSON `{refresh_token}` and returns **only** a new access token (`services/auth.py:61-73`). There is **no rotation and no revocation list**, and logout is a no-op (`api/v1/auth.py:50-57`).
  - `GET /auth/me` exists and validates the token server-side (`api/v1/auth.py:39-47`).
- **Pusher:** `pusher` / `pusher-js` are dependencies, but **no file in `src` imports them**. Realtime is not wired, so nothing on the frontend depends on the bearer token being readable from JS. The backend `POST /realtime/auth` (`api/v1/realtime.py:11-32`) requires a bearer token and checks `kds-store-{store_id}`, so it works through a BFF proxy unchanged when it is wired later.
- **Impact:** Any XSS (none was found, but there is no CSP backstop, see M2), a malicious extension, or a compromised dependency can read a 30-day refresh token, and there is no server-side way to kill it.
- **Fix:** BFF cookie pattern (section 3.1). Frontend-only, with no backend change required.

### M2 — Missing CSP / frame-ancestors / Permissions-Policy (Major)

- **Evidence:** `app/next.config.ts:36-42` sets only `nosniff` and `Referrer-Policy` (the comment says CSP was deferred on purpose). There is no `proxy.ts`/`middleware.ts`. Prod response headers have HSTS (from Vercel: `max-age=63072000; includeSubDomains; preload`), nosniff, and Referrer-Policy. **No CSP, no frame-ancestors/X-Frame-Options, no Permissions-Policy.**
- **Impact:** No XSS backstop while tokens sit in localStorage. The POS can be framed by any site, so clickjacking against void/backdate/pay actions is possible.
- **Fix:** See section 3.2 (nonce CSP in `proxy.ts`, Report-Only first) and section 3.3 (static headers).

### M3 — Local print bridge accepts any web origin (Major)

- **Evidence:**
  - `bridge/server.mjs:664-666` sends `Access-Control-Allow-Origin: *`.
  - `:684` checks the token **only if** `BRIDGE_TOKEN` is set, and `app/src/lib/printer-bridge.ts:32-35` never sends `x-bridge-token`, so in practice the bridge runs with no token.
  - `:716-718` calls `JSON.parse(raw)` without checking `Content-Type`. That means a cross-site `POST /print` with `Content-Type: text/plain` is a CORS "simple request" with no preflight.
  - `GET /config` and `/scan` can be read cross-origin because of ACAO `*`.
  - `PUT /config` is blocked by the preflight, but only by accident: `PUT` is missing from `Allow-Methods` at `:665`.
- **Impact:** Any page the cashier opens on the POS PC (ads, phishing) can print forged receipts and read store/printer config. Chrome's Local Network Access prompt only partly mitigates this, and other browsers differ.
- **Fix:**
  - Allow only the exact prod origin(s) (plus localhost in dev). Reflect the origin only when it matches, and reject any other `Origin` with 403.
  - Require `Content-Type: application/json`, which forces a preflight.
  - Generate a per-install `BRIDGE_TOKEN` and send it from the app. A shop-wide token served via an authenticated BFF route is fine.
  - Send `Access-Control-Allow-Private-Network: true` only for allowed origins.

### M4 — PIN login brute-force and lockout (Major)

- **Evidence:**
  - `api/app/api/v1/auth.py:23` sets `@limiter.limit("5/minute")` with `key_func=get_remote_address` (`core/ratelimit.py:4`).
  - Uvicorn starts **without** `--proxy-headers --forwarded-allow-ips` (`Procfile`, `railway.toml:5`). So `request.client.host` is the Railway proxy, and with the Vercel rewrite in front, Vercel's egress IP. The result is one bucket shared by **every user of every store** (5 typos/min from anyone locks everyone out). Or, if the bucket ends up per edge IP, the limit doesn't stop distributed guessing.
  - `services/auth.py:25-44` tries the PIN against **all** active users in the store, so the effective guess space is 10⁴ ÷ N for a 4-digit PIN. It also runs N bcrypt-12 verifies per request, which adds CPU DoS.
  - `/auth/refresh` (`auth.py:29-36`) has no limit.
  - Frontend `login.tsx:40-59,81` only shows a cooldown countdown from `Retry-After`.
- **Fix:**
  - **Frontend (in scope):** The BFF `POST /api/auth/login` adds an Upstash rate limit keyed on the real client IP (`x-forwarded-for` first hop on Vercel) **and** `store_slug`, e.g. 5/min/IP and 20/15 min/store with a progressive delay. It also forwards `X-Forwarded-For` to Railway.
  - **Backend follow-up:** Trust the forwarded headers from the Vercel BFF only, using a shared secret header, because Railway has no fixed proxy IP. Add per-store/per-user lockout with exponential backoff. Enforce 6-digit PINs for OWNER/MANAGER. Rate-limit `/auth/refresh`.

### M5 — Backend RBAC gaps (Major, backend follow-up)

Client role checks are UI-only (`app/src/components/app-common.tsx:141-152,156-170`). That is acceptable **only if** the backend enforces every rule. The backend does scope all queries by `store_id` taken from the token (no IDOR found in the sampled services). The role gaps are below.

| Endpoint | Allowed today | Risk | Suggested |
|---|---|---|---|
| `POST /orders/{id}/void` (`orders.py:117`) | all staff | Cash skimming: take cash, void order | MANAGER+ or manager PIN override |
| `PATCH /orders/{id}/date` (`orders.py:137`) | all staff | Re-numbers receipts and shifts `created_at` (tax/audit integrity) | OWNER/MANAGER + audit log |
| `POST /stock-takes` (`stock_takes.py:20`) | any store user | Hides inventory theft through variance adjustments | MANAGER+ (or two-step approval) |
| `GET /hr/staff`, `/hr/staff/{id}` (`hr.py:40,51`) | any store user | Phone, email, and address of all staff (PDPA) | MANAGER+, or a reduced `StaffPublic` schema |
| `pre-orders/*`, `production-orders` POST | any store user | Business-rule question | Confirm with owner |
| `POST /auth/logout` | no-op | Stolen tokens stay valid | `token_version` on User, checked in `decode_token` |

### M6 — Dependency advisories (Major)

- **`pnpm audit` (2026-10-04):** low 6, moderate 50, **high 54, critical 6**.
  - Critical: `next` ×3 (B1), `next-auth@5.0.0-beta.31` ×2, `@auth/core` ×1.
  - High is dominated by `next`, `brace-expansion`, `fast-uri`, `js-yaml`, `nanoid`, `sharp`, `form-data` (via `pusher`), `vite`, and `hono` (via `prisma` dev).
- **Unused** (0 imports in `src`, verified by grep): `next-auth`, `@auth/prisma-adapter`, `@prisma/client`, `@prisma/adapter-pg`, `prisma`, `pg`, `bcryptjs`, `@trpc/*`, `superjson`, `pusher`, `pusher-js`, `promptpay-qr`, `qrcode` (plus `@types/*` for them). `src/lib/db.ts` and `prisma/` are dead. `postinstall`/`vercel-build` run `prisma generate` for nothing.
- **Fix:**
  - Remove the unused packages and the scripts that call them, delete `src/lib/db.ts`, and decide whether to keep `prisma/` as an archive.
  - Keep `zod` (needed for BFF validation).
  - Upgrade `next` (B1) and run `pnpm up` for the transitive ones.
  - Target: `pnpm audit --audit-level high` exits clean, or each remaining item is dev-only and documented.

### m1 — image-proxy hardening (Minor)

`app/src/app/api/image-proxy/route.ts`:
- `:17` accepts any `*.r2.dev`, which makes it an open relay for any public R2 bucket.
- `:46` uses `redirect: 'follow'`, so an allowlisted host that redirects can reach any URL (allowlist bypass).
- There is no auth and no size cap.

The response is already sandboxed (`next.config.ts:44-53`, good).

**Fix:** pin the exact bucket host, use `redirect: 'error'`, require a session cookie after the BFF lands, cap `Content-Length` at about 10 MB, and allowlist `image/(png|jpeg|webp|avif)` (drop SVG).

### m2 — Unused Epson ePOS SDK on every page (Minor)

`app/src/app/layout.tsx:76` loads `/epos-2.27.0.js`, but nothing in `src` references `epson`/`ePOSDevice`. **Fix:** remove it (or load it only on the hardware screen). That leaves one fewer script to trust under CSP.

### m3 — Shopping-list print opens without auth (Minor, functional)

`app/src/components/screens/shopping-list.tsx:108` opens `/api/v1/shopping-list/print` in a new tab with no bearer, and the backend requires `StoreUser` (`shopping_list.py:22-25`), so it always returns 401. This works automatically once the BFF cookie proxy is in place. Until then, fetch it with `api.get` and open a Blob.

### m4 — `NEXT_PUBLIC_API_BASE_URL` (Minor)

`app/.env.example` sets it to the Railway URL, and `src/lib/api-client.ts:4`, `auth.ts:3`, and `login.tsx:19` honour it. With the BFF it **must** be empty. **Fix:** remove the variable and always use same-origin paths.

### m5 — Public OpenAPI on Railway (Minor, backend follow-up)

`https://caf-pos-repo-production.up.railway.app/docs` → 200. **Fix:** set `docs_url=None, openapi_url=None` when `ENVIRONMENT=production`.

### m6 — Server bound to 0.0.0.0 (Minor)

`app/package.json` scripts `dev`/`start` use `-H 0.0.0.0`. This is fine on Vercel. On a shop PC it exposes the app, including B2 and the Windows RCE advisory, to the LAN. **Fix:** default to `127.0.0.1` and add a separate `dev:lan` script when tablet testing is needed.

## 3. Hardening plan (concrete)

> Next 16 confirmed: `node_modules/next/dist/lib/constants.js` has `PROXY_FILENAME = 'proxy'`. The file is **`src/proxy.ts`** exporting `function proxy(request)`. It runs on the **Node.js runtime** by default (setting `runtime` throws). See `node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md` and `.../backend-for-frontend.md`.

### 3.1 BFF + httpOnly cookies (fixes M1, m3, part of M4)

Cookies (names use the `__Host-` prefix: path `/`, `Secure`, no Domain):

| Cookie | Content | Flags | Max-Age |
|---|---|---|---|
| `__Host-pos_at` | access JWT | `HttpOnly; Secure; SameSite=Strict; Path=/` | 8 h (match `exp`) |
| `__Host-pos_rt` | refresh JWT | `HttpOnly; Secure; SameSite=Strict; Path=/` | 30 d (rotate when backend supports it) |

Routes (all `runtime = 'nodejs'`, Zod-validated, `Cache-Control: no-store`):
- `POST /api/auth/login`: Zod `{store_slug: string 1-60, pin: /^\d{4,6}$/}`. Upstash rate limit (IP + slug). Forward to `${RAILWAY_API_URL}/api/v1/auth/login` with `X-Forwarded-For`. On 200, set both cookies and return `{ ok: true }` (**never** the tokens). Pass 401/429 through along with `Retry-After`.
- `POST /api/auth/refresh`: read `__Host-pos_rt` and call backend refresh. Set a new `__Host-pos_at`. If refresh fails, clear both cookies and return 401.
- `POST /api/auth/logout`: call backend logout (best effort) and clear both cookies.
- `GET|POST|PUT|PATCH|DELETE /api/v1/[...path]`: replaces the `rewrites()` entry in `next.config.ts`.
  - Read `__Host-pos_at` and attach `Authorization: Bearer`.
  - **Strip** any client-supplied `Authorization`/`Cookie` before forwarding.
  - Stream the body and pass status and `Retry-After` through.
  - On a 401, do a server-side refresh once and retry.
  - Allowlist path segments (`/^[\w\-./]+$/`, reject `..`).
  - The upstream base is fixed from env and never built from user input (this prevents SSRF).
  - Covers `/realtime/auth` for Pusher later.
- **CSRF:** `SameSite=Strict` plus an `Origin`/`Sec-Fetch-Site` check in `proxy.ts` on all non-GET `/api/*`. Reject if `Origin` ≠ own origin.
- **Client changes:** `token-store.ts` becomes an auth-state flag only, driven by `GET /api/v1/auth/me`. `api-client.ts` drops the `Authorization` header and refresh logic (or calls `/api/auth/refresh`). `login.tsx` posts to `/api/auth/login`. `useCurrentUser` stays.
- **Migration:** on first load, if a legacy `cafe_pos_token` exists in localStorage, delete it and send the user to login. This is a one-time re-login per tablet.
- **SW:** `sw.js` already bypasses `/api/*` (`sw.js:7,235-236`). Keep it that way.

### 3.2 CSP via `src/proxy.ts` (fixes M2) — Report-Only first

```
default-src 'self';
script-src 'self' 'nonce-{N}' 'strict-dynamic';
style-src 'self' 'unsafe-inline';            # 2,700+ React style={{}} attrs; nonce would disable unsafe-inline
img-src 'self' data: blob: https://<exact-bucket>.r2.dev [https://<R2_PUBLIC_URL host>];
font-src 'self';                              # next/font self-hosts Anuphan
connect-src 'self' http://127.0.0.1:8080 [wss://ws-ap1.pusher.com https://sockjs-ap1.pusher.com when Pusher is wired];
worker-src 'self';                            # public/sw.js
manifest-src 'self';
frame-ancestors 'none';
base-uri 'none';
form-action 'self';
object-src 'none';
upgrade-insecure-requests;                    # leave out while bridge is http://127.0.0.1 if it causes issues (loopback is exempt in Chrome)
report-to csp; report-uri /api/csp-report
```
- Dev adds `'unsafe-eval'` (React debug).
- Sources needed by this app:
  - PromptPay QR is `qr_image_base64` from the backend → `data:`.
  - Image crop / XLSX export → `blob:`.
  - The inline theme script in `layout.tsx:69-73` gets the nonce: make `RootLayout` async, read `(await headers()).get('x-nonce')`, pass `nonce` to `<script>`. Reading `headers()` also forces dynamic rendering, which nonces require.
- Matcher: exclude `_next/static`, `_next/image`, `favicon.ico`, `icons/`, `sw.js`, `manifest.webmanifest`, `epos-*.js`, and prefetch requests (`missing: next-router-prefetch / purpose=prefetch`), as the Next 16 CSP guide shows.
- Rollout:
  1. Ship `Content-Security-Policy-Report-Only` plus a small `/api/csp-report` route that logs (rate-limited, body ≤ 8 KB).
  2. Run Playwright through login → sell → pay (cash/QR) → print → reports → image crop → install PWA, and watch console violations and reports for about 1 week on tablets.
  3. Switch to enforcing.
- Do this **after** the B1 upgrade (proxy-bypass advisories are fixed in ≥16.2.6/16.3.x).

### 3.3 Static headers (`next.config.ts`, all routes)
- `X-Frame-Options: DENY` (legacy fallback to `frame-ancestors`).
- `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), serial=(), bluetooth=()`. Turn `camera` back on with `(self)` only if barcode scanning by camera is added.
- `Cross-Origin-Opener-Policy: same-origin`.
- HSTS is already sent by Vercel. Set it explicitly too (`max-age=31536000; includeSubDomains`) so it survives a custom domain or a non-Vercel host.
- Keep the existing `nosniff`, `Referrer-Policy`, and image-proxy sandbox.

### 3.4 If any Node-side printer route must come back (not recommended)
- Auth: either call backend `GET /api/v1/auth/me` with the cookie token (simplest, about one extra RTT, cache 60 s per token hash), or verify HS256 locally with `jose` using a shared `JWT_SECRET`. Sharing the secret widens blast radius, so prefer `/me`. Require role OWNER/MANAGER for config.
- Validation: Zod-validate the body, cap `items` at 200 and string length at 120, and strip bytes below 0x20 except LF.
- Target allowlist: IP must be a **literal** in RFC1918 (`10/8`, `172.16/12`, `192.168/16`). Reject loopback, link-local `169.254/16`, and hostnames. Port must be in `{9100, 9101, 9102}`.
- Never accept the target IP from the request body at print time. Read it from server config only.

### 3.5 Bridge (M3)

**Design notes**
- Cookies: `__Host-pos_at` (HttpOnly, Path=/, lifetime from JWT `exp`, max 8 h), `__Secure-pos_rt` (HttpOnly, Path=/api/auth, max 30 d), `pos_session=1` (non-HttpOnly flag the client reads to decide login vs app; same lifetime as the refresh cookie). All `Secure; SameSite=Strict`. Plain-HTTP loopback dev drops `Secure` and the prefixes.
- CSRF: Origin (or `Sec-Fetch-Site: same-origin`) is required on every non-GET `/api/*`, checked in `proxy.ts` **and** again in each BFF handler. `ALLOWED_ORIGINS` env adds exact origins.
- `/api/v1/*` proxy: fixed upstream from `RAILWAY_API_URL` (https only), path segments decoded, validated and re-encoded, client `Authorization`/`Cookie` never forwarded, upstream `Set-Cookie`/CORS headers dropped, off-origin redirects dropped, `Cache-Control: no-store` + sandbox CSP on every response.
- Compatibility: `/api/v1/auth/login` still works for the current login screen (sets cookies, returns `access_token: "cookie-session"`, never a token). When a session is already active it returns **409** instead, so a second-person PIN check can never replace the cashier's session. `/api/v1/auth/refresh` always returns 401, so old tabs fall back to login once.
- Manager approval: `POST /api/auth/verify-pin` checks a second PIN and returns `{user, same_store}` without touching cookies.
- Rate limits (in-memory, per warm instance): failed logins 5/min/IP and 20/15 min/store (shared by verify-pin); refresh 30/min/IP; csp-report 30/min/IP.
- Service worker `v2`: the `/` shell is still cached for the offline banner even though it is now dynamic (`no-store`). It carries no user data. `/api/*` is never cached.
